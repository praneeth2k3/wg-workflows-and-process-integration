# Low-Code / Visual Orchestration

n8n, Zapier, Make, and Workato — visual, connector-driven automation for non-developers, now layering agentic capability onto what was originally a fixed automation model. Part of the [landscape survey](README.md); see [`../references.md`](../references.md) for sourcing.

## n8n

n8n (see [n8n documentation](https://docs.n8n.io/)) models a workflow as a directed graph of nodes, where each node is either a trigger node (starts an execution) or an action node (performs work), connected by edges that carry data from one node's output to the next node's input. Branching is handled by IF and Switch nodes (n8n's nearest equivalent to `P3 Decision`), and a Wait node pauses execution for a duration or until a condition (n8n's nearest equivalent to `P8 TimerDeadline`). Its **AI Agent node** is the most directly relevant construct in this whole landscape: it accepts typed sub-node attachments for a chat model, a memory store, and a set of tools, giving a visual, declarative way to compose an agent's capability set without writing the agent's control loop by hand. n8n supports sub-workflow-as-tool (a whole other n8n workflow, invoked as if it were a single tool call), human-in-the-loop `sendAndWait` operations that pause a workflow until a human responds through a form or a chat message, dedicated error workflows that a failing execution can be routed to, and per-node retry settings. Each run's execution data — the same underlying mechanism the RA's cross-mapping tables cite for both `P12 StateCommit` and `P15 AuditRecord` — is n8n's record of what happened during a workflow run.

n8n is not a standard, has no governing standards body, and is not part of the reference list's standards-and-foundations group — and it matters to a standards effort anyway. n8n is where an unusually large population of practitioners — many with no BPMN or formal workflow-engine background — is actually meeting agentic workflow concepts for the first time, through its AI Agent node's tool-attachment UI. A primitive vocabulary that a n8n user cannot recognize in their own tool ("oh, that typed tool connection is what they mean by `P5 ToolCall`'s effect classification") is a vocabulary that will not get adopted by that population regardless of its technical merit, because adoption requires the reader to map the new term onto something they already do. This is why `ra-single-agent.md`'s and `ra-multi-agent.md`'s cross-mapping tables give n8n equal billing with BPMN, Temporal, and LangGraph, despite n8n being a product rather than a specification.

**What n8n gives for free:** a visual tool-attachment model that already resembles the `AgentStep` tool-scope contract's shape, a durable human-pause primitive (`sendAndWait`), and per-node retry — all without requiring the user to reason about an underlying execution engine. **What it does not give:** no budget ceiling on an agent loop, no compensation mechanism (`ra-single-agent.md`'s cross-mapping table marks this "a real gap"), and no dedicated fan-out/fan-in node — concurrent work has to be composed from batching and merge nodes rather than expressed as one first-class construct.

## Zapier, Make, Workato

Zapier, Make, and Workato occupy the same low-code space as n8n — each lets a non-developer wire triggers to actions across SaaS applications, and each has begun layering agentic capability (an AI-driven step that can choose among a bounded set of actions) on top of what was originally a fixed automation model.

> **[verify]** This document does not have a verified source in its reference list for Zapier's, Make's, or Workato's specific current agentic feature set, construct names, or terminology, and does not assert specifics about them as fact.

Workato's relevance to this WG is direct and confirmed independently of its product specifics: per the [WG charter](../../../../charter/charter.md), Adam Seligman — of Workato — is the WG's co-chair. That gives Workato's own agentic-automation model (whatever its current specifics turn out to be on verification) a standing inside this WG's process that the RA's authors should not treat as incidental, for the same reason Dapr's standing matters to the chair's affiliation (see [`durable-execution.md`](durable-execution.md)): a co-chair's own platform diverging gratuitously from the WG's reference architecture would be a visible and avoidable inconsistency.
